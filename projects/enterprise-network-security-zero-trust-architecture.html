A. Project Overview

Problem Statement

Traditional perimeter-based security assumes that anything inside the network boundary can be trusted, but this leaves organizations highly exposed once any single internal device or credential is compromised, since lateral movement is largely unrestricted.

Proposed Solution

A Zero Trust-aligned architecture where network segments are strictly firewalled from each other by default, all access requires explicit authentication against centralized identity (FreeIPA/Active Directory), remote access uses modern VPN technology (WireGuard), and Wazuh plus IDS/IPS provide continuous security monitoring and centralized logging.

Objectives

  • Implement network segmentation aligned with Zero Trust principles.
  • Centralize authentication and authorization across all network resources.
  • Deploy firewall policies, VPN access and intrusion detection/prevention.
  • Establish centralized security logging and auditing.

Intended Users

Security/network administrators, compliance officers, and any staff requiring secure remote or segmented internal access.

B. Business Value

Operational BenefitsLimits lateral movement of any compromised device/credential by default, rather than relying solely on perimeter defenses.
Cost OptimizationPrimarily built on open-source tooling (pfSense/OPNsense, WireGuard, Wazuh), minimizing licensing costs relative to commercial security appliances.
ProductivityModern VPN (WireGuard) provides fast, low-overhead secure remote access without the performance penalties of older VPN technologies.
ScalabilitySegmentation and policy rules can be extended as new network zones or user groups are added.
Security & ReliabilityDirectly improves the organization's security posture through defense-in-depth principles.
Organizational ImpactProvides the security foundation that protects every other infrastructure project in this portfolio — AI platforms, HPC clusters, EDA design data, and storage systems all depend on this layer for protection.

C. Technical Architecture

Architecture Overview

A segmented network where firewalls (pfSense/OPNsense) enforce policy between VLANs, all user/device authentication routes through centralized identity, remote users connect via WireGuard VPN into specific authorized segments only, and Wazuh/IDS/IPS continuously monitor for anomalous activity.

graph LR U[User / Client] --> GW[Application / Gateway Layer] GW --> CORE[Enterprise Network Security Core Services] CORE --> DATA[(Data / Storage Layer)] CORE --> MON[Monitoring & Observability] MON --> ADMIN[Administrator]

Components

  • pfSense/OPNsense firewalls
  • VLAN-segmented network zones
  • FreeIPA/Active Directory centralized identity
  • WireGuard VPN gateway
  • IDS/IPS (intrusion detection/prevention)
  • Wazuh (security monitoring/SIEM-like capability)
  • Centralized logging infrastructure

Data Flow

User/device requests access → authenticates against FreeIPA/Active Directory → firewall policy evaluates whether the authenticated identity is authorized for the requested network segment → if remote, WireGuard VPN establishes an encrypted tunnel scoped to authorized segments only → all access and security events logged centrally and monitored by Wazuh/IDS-IPS.

Integration Architecture

Applies as a security overlay across all other infrastructure projects — AI platforms, HPC/EDA compute farms, and storage systems all sit behind this segmentation and monitoring layer.

D. Technology Stack & Rationale

TechnologyWhy It Was Selected
WireGuardModern VPN protocol with a much smaller codebase and better performance than legacy IPsec/OpenVPN, simplifying both security auditing and user experience.
pfSense/OPNsenseMature, well-documented open-source firewall platforms capable of enterprise-grade policy enforcement without commercial licensing costs.
WazuhOpen-source security monitoring providing SIEM-like log correlation and alerting, suited to centralizing visibility across a segmented network.
FreeIPA/Active DirectoryCentralized identity is the foundation Zero Trust is built on — every access decision depends on confidently knowing who/what is making the request.

E. Hardware Requirements

CPUFirewall appliances sized to expected throughput; software firewalls (pfSense/OPNsense) on commodity server hardware scale with core count and NIC offload capability.
GPUNot applicable.
RAM16–32GB typical for firewall/VPN gateway hosts depending on concurrent session/tunnel count.
StorageSufficient storage for centralized log retention (Wazuh/SIEM data can grow significantly depending on retention policy).
NetworkingMultiple NICs per firewall host to physically or logically separate zones; throughput sized to inter-zone traffic volume.
Recommended ConfigurationA dedicated firewall appliance or server per major site/zone boundary, with centralized logging infrastructure sized to total log volume across all zones.
Estimated, not tested: Sizing is estimated guidance; actual throughput and log volume requirements should be measured against real traffic patterns.

F. Software Architecture

Operating SystempfSense/OPNsense (FreeBSD-based) for firewall appliances; Linux for Wazuh/logging infrastructure.
DependenciesWireGuard kernel module/userspace tools, Wazuh agents on monitored hosts, IDS/IPS engine (e.g. Suricata, commonly integrated with pfSense/OPNsense)
ServicesFirewall/VPN gateway service, Wazuh manager, Centralized log aggregation
DatabasesWazuh's indexer (typically OpenSearch-based) for security event storage.
APIsFirewall management APIs for configuration automation; Wazuh API for programmatic security event queries.
MonitoringWazuh dashboards for security event visibility; IDS/IPS alerting for active threat detection.
AutomationInfrastructure-as-code approach to firewall rule management to avoid configuration drift.

H. Security & Reliability

AuthenticationAll access requires authentication against centralized identity; no implicit trust based on network location alone.
AuthorizationExplicit firewall policy per segment, following least-privilege principles.
Network SecurityStrict VLAN segmentation with default-deny policy between zones.
BackupFirewall configuration and Wazuh rule sets backed up and version-controlled.
MonitoringContinuous Wazuh-based security event monitoring and IDS/IPS alerting.
Disaster RecoveryDocumented firewall/VPN gateway recovery procedure.
High AvailabilityRedundant firewall pairs (active/passive or active/active) for environments requiring continuous availability.

I. Testing & Validation

  • Segmentation test: verify default-deny policy blocks unauthorized inter-zone traffic.
  • VPN scoping test: confirm remote users can only reach explicitly authorized segments.
  • IDS/IPS test: validate detection against known attack signatures/patterns in a controlled test.
  • Logging test: confirm all access and security events are captured centrally and correlated correctly.
Test scenarios describe planned validation criteria for this project's current status (Concept). No completed test results are claimed here.
