Automated RTL-to-GDSII Semiconductor Design Pipeline

A. Project Overview

Problem Statement

Commercial RTL-to-GDSII flows (Cadence/Synopsys) are powerful but expensive and license-gated, making them inaccessible for education, open-source hardware projects, and rapid low-risk prototyping; an automated open-source alternative fills this gap.

Proposed Solution

An OpenLane-orchestrated flow chaining Yosys (synthesis), OpenROAD (floorplanning, placement, CTS, routing), OpenSTA (static timing analysis), and Magic/KLayout (DRC/LVS and layout viewing), targeting the open SkyWater 130nm PDK, with functional verification via Verilator/Icarus Verilog prior to synthesis.

Objectives

  • Automate the full RTL-to-GDSII flow using open-source digital design tools.
  • Validate functional correctness via simulation before synthesis.
  • Perform synthesis, floorplanning, placement, clock tree synthesis and routing.
  • Produce a DRC-clean GDSII layout targeting an open PDK (e.g. SkyWater 130nm).

Intended Users

Digital IC design students/educators, open-source silicon hobbyist projects, and engineering teams prototyping designs before committing to costly commercial flows.

This project clearly distinguishes open-source digital design tooling (Yosys/OpenROAD/Magic/OpenLane, used here) from commercial EDA platforms (Cadence/Synopsys, used in Projects 07–08) — the two serve different purposes: open-source flows for education, prototyping and open silicon; commercial flows for production-grade advanced-node analog/mixed-signal and full-custom design.

C. Technical Architecture

Architecture Overview

A staged pipeline orchestrated by OpenLane, where each stage consumes the previous stage's output: RTL → synthesized netlist → floorplan → placed design → clock-tree-inserted design → routed design → GDSII, with verification and timing checks interleaved.

graph LR U[User / Client] --> GW[Application / Gateway Layer] GW --> CORE[Automated RTL-to-GDSII Semic Core Services] CORE --> DATA[(Data / Storage Layer)] CORE --> MON[Monitoring & Observability] MON --> ADMIN[Administrator]

Components

  • Verilator/Icarus Verilog (RTL simulation)
  • Yosys (logic synthesis)
  • OpenROAD (floorplanning, placement, CTS, routing)
  • OpenSTA (static timing analysis)
  • Magic (DRC, layout)
  • KLayout (layout viewing/verification)
  • SkyWater 130nm open PDK

Data Flow

Verilog RTL → functional simulation (Verilator/Icarus) confirms correctness → Yosys synthesizes RTL to a gate-level netlist using PDK standard cells → OpenROAD performs floorplanning, placement and clock tree synthesis → OpenROAD routing produces a fully routed design → OpenSTA verifies timing closure → Magic/KLayout perform DRC/LVS and generate final GDSII.

Integration Architecture

Can run as standalone scripted jobs on the HPC cluster (Project 04) compute nodes, since these are open-source CLI tools with no license server dependency.

D. Technology Stack & Rationale

TechnologyWhy It Was Selected
OpenLaneProvides pre-built orchestration gluing together Yosys/OpenROAD/Magic into a coherent flow, avoiding the need to hand-script every stage transition.
OpenROADThe leading open-source place-and-route engine, actively maintained and capable of producing tape-out-quality results for supported open PDKs.
SkyWater 130nm PDKThe most mature fully open-source PDK available, enabling genuinely manufacturable (via efabless/Skywater shuttle programs) open-source silicon.
YosysThe standard open-source RTL synthesis tool, well integrated with the rest of the open EDA ecosystem.

E. Hardware Requirements

CPUMulti-core CPU for parallelizable stages (placement/routing can be CPU-intensive on larger designs).
GPUNot required — the open-source digital flow tooling (Yosys/OpenROAD/Magic) is CPU-based.
RAM16–64GB depending on design size; larger designs with more standard cells need more memory for placement/routing.
StorageModerate storage for PDK files, intermediate design databases (netlists, DEF/LEF files) and GDSII outputs.
NetworkingStandard LAN sufficient; no special interconnect requirements for single-node flow execution.
Recommended ConfigurationA single capable workstation/server node is typically sufficient for small-to-moderate digital designs on this flow.
Estimated, not tested: Runtime and resource needs scale with design complexity (cell/gate count); figures are general estimates for small-to-moderate designs.

Network SecurityNo external network dependency once PDK and tools are locally installed.

MonitoringFlow run logs retained for debugging failed stages.

High AvailabilityNot applicable — this is a batch pipeline, not a continuously available service.

I. Testing & Validation

  • Functional test: RTL simulation must pass before synthesis proceeds.
  • Timing test: OpenSTA must report timing closure against the target clock constraint.
  • DRC/LVS test: Magic-generated layout must pass design rule and layout-vs-schematic checks.
  • Regression test: confirm flow produces consistent results across repeated runs of the same RTL.
Test scenarios describe planned validation criteria for this project's current status (Concept). No completed test results are claimed here.

J. Deliverables

  • Automated, reproducible RTL-to-GDSII flow for the target open PDK.
  • DRC-clean GDSII layout output for completed designs.
  • Timing and DRC/LVS verification reports.
  • Documented flow configuration for reuse on future designs.

K. Future Enhancements

  • Extension to additional open PDKs as they mature.
  • CI-integrated flow triggering automatically on RTL commits.
  • Comparison benchmarking against commercial flow results on the same design where feasible.
