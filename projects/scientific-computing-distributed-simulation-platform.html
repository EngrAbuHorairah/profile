A. Project Overview

Problem Statement

Scientific and engineering simulation codes (CFD, structural analysis, numerical modeling) require carefully tuned compiler toolchains and numerical libraries, and inconsistent environments across machines lead to non-reproducible results and wasted debugging time.

Proposed Solution

A dedicated scientific computing environment layered on the HPC cluster (Project 04), using Spack to manage multiple compiler (GCC, Intel oneAPI) and library (BLAS, LAPACK, FFTW) versions side-by-side, with MPI/OpenMP providing the parallel execution models applications need.

Objectives

  • Support parallel computation via MPI (distributed) and OpenMP (shared-memory) models.
  • Provide optimized numerical libraries (BLAS/LAPACK/FFTW) for scientific applications.
  • Maintain reproducible, version-controlled software environments.
  • Benchmark application performance across different compiler/library configurations.

Intended Users

Computational scientists, simulation engineers, and research groups running CFD, FEA, or other numerically intensive codes.

C. Technical Architecture

Architecture Overview

Built on top of the HPC cluster's compute nodes, this platform adds a managed software environment layer (via Spack and environment modules) plus parallel runtime libraries (MPI/OpenMP) used by scientific applications.

graph LR U[User / Client] --> GW[Application / Gateway Layer] GW --> CORE[Scientific Computing & Distr Core Services] CORE --> DATA[(Data / Storage Layer)] CORE --> MON[Monitoring & Observability] MON --> ADMIN[Administrator]

Components

  • Spack package manager
  • Environment Modules / Lmod
  • MPI implementation (OpenMPI)
  • OpenMP runtime (bundled with compilers)
  • Optimized numerical libraries: BLAS, LAPACK, FFTW
  • GCC and Intel oneAPI compiler toolchains

Data Flow

Researcher loads a specific software environment (module load) → compiles or runs a simulation code linked against the chosen BLAS/LAPACK/FFTW build → MPI distributes the computation across cluster nodes → OpenMP parallelizes within each node's cores.

Integration Architecture

Runs on the same Slurm-managed cluster (Project 04) and is monitored through the same observability platform (Project 05).

D. Technology Stack & Rationale

TechnologyWhy It Was Selected
SpackAllows multiple versions of compilers and libraries to coexist cleanly, which is essential since different scientific codes require different, sometimes conflicting, dependency versions.
Intel oneAPIProvides highly optimized math kernels (MKL) that often significantly outperform generic library builds on Intel hardware.
FFTWThe standard high-performance library for fast Fourier transforms, used across many simulation and signal-processing codes.
MPI + OpenMP (hybrid)Combining distributed-memory (MPI) and shared-memory (OpenMP) parallelism is the standard approach for scaling scientific codes efficiently across multi-node, multi-core clusters.

E. Hardware Requirements

CPUHigh core-count CPUs with strong per-core performance, as most scientific codes are CPU-bound.
GPUOptional, only for applications with GPU-accelerated solvers.
RAMMemory sized to the largest expected simulation working set; scientific workloads are often memory-bandwidth sensitive.
StorageFast shared storage for simulation input/output datasets, which can be large for CFD/FEA workloads.
NetworkingLow-latency interconnect (InfiniBand/RoCE) important for MPI-heavy codes with frequent inter-node communication.
Recommended ConfigurationLeverages the same compute nodes as Project 04; no separate hardware required beyond compiler/library installation.
Estimated, not tested: Actual performance is highly application-dependent; benchmarking with representative codes is required before capacity planning.

I. Testing & Validation

  • Correctness test: validate numerical library outputs against known reference results.
  • Performance test: benchmark representative codes across different compiler/library builds.
  • Scaling test: measure MPI strong/weak scaling behavior for representative simulation codes.
  • Reproducibility test: confirm identical results across repeated runs with the same environment.
Test scenarios describe planned validation criteria for this project's current status (Concept). No completed test results are claimed here.

J. Deliverables

  • Documentation for researchers on selecting and loading environments.
